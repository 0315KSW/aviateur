# 10. 11/2 (3일차) 회의

근거: 회의 녹음 28:53(음성인식 모델 두 개로 받아 적어 대조)과 손글씨 메모 1장. 녹음은 업체가 360 툴을 보여 주려던 중에 끊깁니다.
두 모델이 같은 뜻으로 받은 부분은 그대로 적었고, 흔들리는 부분은 "추정" 또는 "불명확"으로 표시했습니다.

## 결론
1. 지금 구조(라파 → LAN → 미니PC → WFB-ng 5.8GHz → AGX → LAN → PC)가 맞다고 업체가 확인했습니다.
2. 지연에 대한 업체 의견
   - FFmpeg 기반 프로그램(Aviateur, VLC)은 지연을 못 줄인다.
   - RTP·RTSP와 TCP는 버리고 UDP로 바로 보낸다.
   - GStreamer를 그대로 쓴다.
   - 센서 데이터가 CPU·RAM을 거치지 않고 하드웨어 인코더로 바로 가게 한다(zero-copy).
3. 최종 결과물은 업체 GCS(지상 관제 프로그램)에 뜯어 넣을 수 있는 **PC 영상 수신 툴**이다. UI는 업체가 만든다.

## 손글씨 메모
```
[Air]                                                      [Ground]
라파(8GB) ─LAN─▶ 미니PC(전송 시스템) ─WFB-ng─▶ Wi-Fi 5.8GHz (50ms) ─▶ AGX ─LAN─▶ PC (Viewer)
|◀───────────────────────── 전체 700ms ─────────────────────────▶|
360° cam ×2
```
- 미니PC 아래 글씨는 "전송 시스템"으로 읽힙니다. 녹음 01:11의 "이게 전송 시스템이고"와 같습니다.
- 50ms는 업체가 말한 무선 구간 값이고, 700ms는 11/2에 우리가 잰 전체 값(Aviateur)입니다.
