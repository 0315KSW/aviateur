# 07. 문제와 해결

| # | 문제 | 원인 | 조치 | 상태 |
|---|---|---|---|---|
| 1 | 수신 시작 즉시 `Unable to read rx secret key` | Aviateur가 키 파일을 텍스트 모드로 열었음. Windows는 텍스트 모드에서 `0x1A`를 파일 끝으로 봄. 당시 `gs.key`는 offset 2와 56이 `0x1A` | 10/27 20:36 키 쌍 재생성으로 우회 → 패치 1에서 `"rb"`로 열도록 수정 | 해결 |
| 2 | RTP는 들어오는데 화면이 안 나옴, `PPS id out of range` 반복 | 수신이 스트림 중간부터 들어와 디코더가 VPS/SPS/PPS를 못 받음 | 송신 GStreamer에 `config-interval=-1` (키프레임마다 헤더 반복) | 해결 (FFmpeg 실시간 경로의 같은 설정 여부는 송신 확인 필요) |
| 3 | 4K·8Mbps·MCS 4에서 수신 No Signal | 미확정 (높은 MCS에서 수신 감도 부족 추정) | MCS 1·낮은 비트레이트로 변경 | 우회 |
| 4 | 12:46 시험이 소프트웨어 디코딩 | Aviateur의 `Force software decoding`이 켜져 있었음 | 끄도록 안내. 13:3x 로그에서 DXVA2 하드웨어 디코딩 확인 | 해결 |
| 5 | **4K 화면 깨짐** | RTP 손실 → 참조 프레임 오류 누적. 손실 위치는 GX10 WFB-ng 이후(송신 동글·전파·수신 동글·USB)로 좁힘 | 송신 출력 15dBm(효과 거의 없음), 수신기 계측 추가(패치 1) | **미해결, 원인 분리 중** |
| 6 | 실시간 4K 중 카메라 USB 끊김 (12:55, 약 2분 11초 후) | 미확정 (1회 발생) | 재시험에서는 10분 유지 | 관찰 필요 |
| 7 | 녹화와 송신 동시 실행 시 16.5fps | 미확정 (카메라 입력·디코딩·인코딩·저장 중 병목 위치 미확인) | 녹화 없이 실시간만 하면 약 29fps | 관찰 필요 |
| 8 | 송신 출력이 재시작 후 원래대로 | 디스크의 설정 파일이 `wifi_txpower = -100`(−1dBm) 그대로 | 재시작 때마다 `iw ... info`로 확인 | 송신 쪽 설정 정리 필요 |
| 9 | 원본 Aviateur로 손실 위치를 알 수 없음 | 내부 카운터를 내보내지 않음, FEC 복구·손실 수 없음 | 패치 1: 초당 CSV, 끊김/복구 이벤트, 로그 파일 | 해결 |
| 10 | 원본 로그 받기가 번거로움 | 숨겨진 콘솔로만 출력, 시각 없음 | 임시: `cmd /c "aviateur.exe > ... 2>&1"` → 패치 1: 시각 포함 로그 파일 | 해결 |
| 11 | RTP 손실이 순환 지점에서 안 잡힘 | 16비트 시퀀스 번호를 int로 빼서 65535→0 지점이 음수 | 패치 1에서 `uint16_t` 차이로 수정 | 해결 |
| 12 | USB 수신 큐 설정(`DEVOURER_RX_URBS`)이 무시됨 | Aviateur가 드라이버에 설정을 넘기지 않음 | 패치 1에서 환경변수 → `DeviceConfig` 전달 | 해결 (A/B 시험은 아직) |
| 13 | 패치 1 로그 파일에 빈 줄 | 로그 콜백 여러 개에 같은 문자열을 move로 넘김 | 패치 1.1에서 복사본 전달 | 해결 (장비 실행 확인 전) |
| 14 | fpv4win 공식 빌드 없음 | Releases 없음, Actions 실행 0건 | Aviateur 선택 | — |

## 판단을 고친 것 (기록)

진행 중 잘못 판단했다가 데이터로 바로잡은 내용입니다. 같은 실수를 반복하지 않기 위해 남깁니다.

| 처음 판단 | 데이터 확인 후 |
|---|---|
| "SNR이 안정적이라 신호 세기는 원인이 아니다" | 회차별로 보면 SNR이 손실과 함께 움직임(33.7dB vs 27.3dB). 무선 상태를 원인에서 뺄 수 없음 |
| "송신 쪽 데이터가 시간이 지나며 줄었다" | 송신 주입은 세 구간 모두 일정(17,098 / 18,977 / 18,999), 드롭 0 |
| 10/28 720p를 시험 패턴으로 봄 | Femto 실시간 영상 약 1.5Mbps |
| "송신 드롭은 원인에서 제외" | 제외할 수 있는 것은 GX10의 WFB-ng 단계 드롭뿐. 송신 동글 단계는 제외 못 함 |
| 16:32 세 회차를 USB 큐 8/16/32 비교로 기록 (외부 보고서) | 세 회차 모두 큐 8, Aviateur 한 번 실행, 콘솔 로그 없음. 큐 비교 시험은 아직 안 함 |
