# 05. 수신기 수정 (Aviateur 포크, 패치 1·1.1)

## 왜 고쳤나
- 원본 Aviateur는 무선·WFB·RTP 카운터를 내부에서만 세고 밖으로 내보내지 않습니다. FEC 복구 수, FEC 후 손실 수도 볼 수 없습니다.
- 그래서 "4K가 깨지는 원인이 무선인지, USB인지, 디코딩·표시인지"를 추측으로만 좁힐 수 있었습니다.
- 지연을 줄이는 수정은 **어디가 병목인지 먼저 측정한 뒤** 하기로 했습니다. 패치 1은 측정 기능과 확인된 버그 수정입니다.
- 수신·복호화·FEC·디코딩·표시 로직 자체는 바꾸지 않았습니다.

## 변경 요약

| # | 종류 | 파일 | 내용 |
|---|---|---|---|
| 1 | 버그 수정 | `src/wifi/wfb-ng/rx.cpp` | 키 파일을 `"r"` → `"rb"`(바이너리)로 열기. Windows 텍스트 모드는 `0x1A`를 파일 끝으로 처리해서, 그 바이트가 든 키를 못 읽었음 |
| 2 | 설정 전달 | 새 `src/wifi/devourer_env.h`, `src/wifi/wfbng_link.cpp` | `DEVOURER_RX_URBS` 등 환경변수를 읽어 USB 수신 큐 설정을 드라이버에 넘김. 원본은 넘기지 않아 항상 기본값 8 |
| 3 | 버그 수정 | `src/wifi/wfbng_link.cpp` | RTP 손실 계산의 16비트 순환 오류. 65535→0 지점의 손실이 기록되지 않던 것을 `uint16_t` 차이로 수정 |
| 4 | 계측 | 새 `src/link_stats.h` | 수신 경로 전 구간(무선 프레임 → WFB → FEC 복구/손실 → RTP → 디코딩 → 표시) 초당 통계를 CSV로 기록 |
| 5 | 계측 | `src/link_stats.h` | 300ms 이상 영상 패킷이 없으면 `[EVENT] link lost`, 복귀 시 `link restored`, 첫 화면까지 `recovery` 시간 기록 |
| 6 | 계측 | `src/player/ffmpeg/video_player.cpp/.h` | 디코딩·표시·버림 프레임 수, 디코딩 후 표시까지 대기시간, 디코더 재오픈 기록 |
| 7 | 로그 | `src/gui_interface.h` | 모든 로그 줄에 시각, `logs/aviateur_<시각>.log` 파일 저장, 첫 줄에 빌드 식별자 |
| 8 | 패치 1.1 | `src/gui_interface.h` | 로그 콜백 여러 개에 같은 문자열을 `std::move`로 넘겨 두 번째(파일)부터 빈 줄이 되던 문제 수정. 각 콜백에 복사본 전달 |

### 대표 코드 (패치 1)

키 읽기 (`rx.cpp`)
```diff
-    if((fp = fopen(keypair.c_str(), "r")) == NULL)
+    if((fp = fopen(keypair.c_str(), "rb")) == NULL)
```

RTP 손실 계산 (`wfbng_link.cpp`)
```cpp
const uint16_t diff = static_cast<uint16_t>(seq_num - prev_seq_num.value());
if (diff > 1 && diff < 0x8000) {          // 순환 안전, 역순 패킷은 손실로 안 셈
    const int lost = diff - 1;
    lowlat::LinkStats::I().rtp_gap_events++;
    lowlat::LinkStats::I().rtp_gap_pkts += lost;
}
```

USB 수신 큐 설정 전달 (`wfbng_link.cpp`)
```cpp
std::string rx_cfg_summary;
const devourer::DeviceConfig dev_cfg = lowlat::DevourerRxConfigFromEnv(rx_cfg_summary);
rtlDevice = wifi_driver.CreateRtlDevice(devHandle, ctx, usb_lock, dev_cfg);
```

## CSV 컬럼 (`logs/link_<시각>.csv`, 1초 1줄)

| 컬럼 | 뜻 |
|---|---|
| `wifi_frames` / `wfb_frames` / `video_frames` | 받은 전체 802.11 프레임 / WFB 프레임 / 우리 영상 채널 프레임 |
| `fec_recovered` | 무선에서 잃었지만 FEC로 복구한 패킷 |
| `lost_after_fec` | FEC로도 복구 못 한 패킷 (화면 깨짐의 직접 원인) |
| `rtp_pkts`, `rtp_gap_events`, `rtp_gap_pkts` | RTP 수신, 손실 이벤트, 손실 패킷 |
| `frames_decoded`, `frames_rendered`, `frames_dropped_queue` | 디코딩, 표시, 표시 전 교체된 프레임 |
| `queue_wait_avg_ms`, `queue_wait_max_ms` | 디코딩 후 표시까지 대기 |
| `rssi0_avg`, `rssi1_avg`, `rssi_min`, `snr0_avg`, `snr1_avg` | 안테나별 수신 세기·SNR |
| `read_errors`, `send_errors`, `reopens` | 디코더 오류·재오픈 |

전체 목록은 `PATCH1_CHANGES.md` 4절.

## 실행

zip을 풀고, 같은 폴더의 배치 파일로 실행합니다(콘솔 로그까지 저장됨).

| 파일 | 내용 |
|---|---|
| `run_urbs8.bat` | USB 수신 큐 8 (기본값과 같음) |
| `run_urbs16.bat` / `run_urbs32.bat` | 큐 16 / 32 (USB 단계 손실 여부 A/B 시험용) |
| `run_lowlat.bat` | 위 배치들이 부르는 공통 스크립트. `DEVOURER_RX_RING_MS=1000`, 콘솔 출력 → `logs\console_<시각>_urbsN.txt` |

실행되면 로그 첫 줄에 빌드 식별자가 찍힙니다.
```
Aviateur 0.3.3 + lowlat-rx patch 1.1 ...
[DRIVER] devourer RX config: urbs=16 ...
```
