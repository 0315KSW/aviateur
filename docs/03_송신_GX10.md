# 03. 송신 (GX10, Ubuntu ARM64)

근거: 송신 측 최종 보고「GX10 무선 영상 전송 진행 보고」(2026-10-28)와 송신 측이 전달한 설정값.
송신 PC의 실제 스크립트와 설정 파일은 GX10의 `/home/ikw/wfb-gx10/`에 있습니다.
**정확한 명령과 스크립트는 송신 담당이 `tx/` 폴더에 추가할 예정**입니다. 이 문서에는 확인된 설정과 순서만 적었습니다.

## 1. 무선 동글 드라이버
- RTL8812AU용 WFB 드라이버를 DKMS로 설치 (모듈 이름 `88XXau_wfb`).
- GX10에 Secure Boot가 켜져 있어 **모듈 서명 키를 등록**하는 절차를 거쳤습니다.
- 이후 동글 인터페이스 `wlxfc221c1000f1`이 잡혔고, 동글은 USB 허브를 통해 연결했습니다.
- 참고(공식): 드라이버 [svpcom/rtl8812au](https://github.com/svpcom/rtl8812au), 설치 순서는 [wfb-ng README](https://github.com/svpcom/wfb-ng).

## 2. WFB-ng
- WFB-ng를 설치하고 송신(drone) 서비스를 구성했습니다. 사용 구성 요소: `wfb-server`, `wfb_tx`.
- 키 생성: `wfb_keygen`으로 `drone.key`(송신) / `gs.key`(수신) 쌍을 만듭니다.
  - 10/27 20:36 수신 쪽 문제(→ [07](07_문제와해결.md))를 우회하려고 키 쌍을 재생성했습니다.
- 설정: 채널 36·20MHz, MCS 1, FEC 8/12, FEC 타임아웃 10ms, link ID 7669206, 영상 radio port 0.
- 영상 입력: GX10 내부 UDP 5602 포트로 RTP를 받습니다.
- 송신 출력: 10/28 13:37:12에 `iw`로 15dBm 설정(장치 표시값 15.00dBm 확인). 디스크 설정은 −1dBm(`wifi_txpower = -100`)이므로 **무선 서비스를 다시 시작하면 매번 출력 표시를 확인**해야 합니다:
  ```
  iw dev wlxfc221c1000f1 info
  ```

## 3. 영상 인코딩
### 실시간 (Femto Bolt)
- 경로: Femto Bolt(MJPEG) → FFmpeg `mjpeg_cuvid`(하드웨어 디코딩) → `hevc_nvenc`(하드웨어 H.265 인코딩) → RTP → UDP 5602
- 설정: 3840×2160, 목표 30fps, CBR 목표 3Mbps, VBV 1Mbit, GOP 30프레임, B프레임 0, RTP payload type 96

### 녹화 시험 영상 (초기)
- GStreamer로 RTP 송신.
- 수신 쪽 디코더가 시작하지 못하던 문제("PPS id out of range")를 해결하려고 **키프레임마다 VPS/SPS/PPS를 반복 송신**하도록 `config-interval=-1`을 설정했습니다.
- 이 옵션은 GStreamer 경로에 적용한 것입니다. FFmpeg 실시간 스크립트에 같은 옵션이 명시됐는지는 송신 쪽 확인이 필요합니다.

## 5. 송신 쪽에서 확인된 것과 남은 것
- **확인:** 카메라 입력과 인코더 출력은 정상(로컬 녹화 파일 정상). WFB-ng 송신 드롭 0.
- **남은 것:** 동시 녹화 시험의 16.5fps 병목 위치, 카메라 USB 끊김(1회), "송신 주입"이 실제 전파 송출을 보증하지는 않음.
