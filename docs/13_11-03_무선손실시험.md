# 13. 11/3 무선 손실 시험

화면이 깨지는 원인을 찾으려고 채널·출력·MCS·비트레이트를 하나씩 바꿔 가며 쟀습니다.
수신 값은 AGX에서 [`tools/wfb_link_log.py`](../tools/wfb_link_log.py)로 기록했고, 콘솔 출력 원본은 [`data/link_console/`](../data/link_console)에 있습니다(`_TX`는 송신 미니PC 쪽).

## 결론
1. 손실의 원인은 **ch36 간섭**이었습니다. AGX 스캔에서 ch36에 다른 AP(KW-WIFI)가 잡혔고, 36 ↔ 48을 번갈아 바꾸면 손실이 따라 바뀌었습니다.
2. 확정 설정: **ch48 · 20MHz · MCS2 · STBC0 · 출력 인덱스 1(`wifi_txpower = -100`) · FEC 8/12 · 2Mbps**. 손실 0.90% / 0.77% / 0.35%로 세 번 재현됐습니다. 완전 무손실은 아닙니다.
3. 출력을 올려도(인덱스 1 → 10) 효과가 없었습니다.
4. MCS4는 쓸 수 없습니다(손실 11%).

## 송신 쪽 (미니PC)
| 시각 | in 패킷 | injected 패킷 | injected ÷ in | dropped |
|---|---|---|---|---|
| 20:06 | 13,829 | 25,571 | 1.85 | 0 |
| 20:15 | 13,610 | 24,913 | 1.83 | 0 |
| 21:16 | 13,731 | 24,695 | 1.80 | 0 |

- 송신 dropped·truncated는 모든 시험에서 0이었습니다.
- FEC 8/12면 이론상 1.5배인데 1.8배 가까이 나옵니다. 송신 설정 `fec_timeout=10` 때문에 블록이 덜 찼을 때 빈 패킷으로 채워 보내기 때문입니다(4Mbps에서는 1.63배).
- 무선 도착률(AGX `recv` ÷ 송신 `injected`, 같은 시간대)은 81~87%입니다. 원인은 아직 모릅니다(안테나·동글·USB 같은 하드웨어 쪽으로 봄).

## 해석할 때 주의 (송신 담당 지적 반영)
- 화면이 깨지는지는 `lost`로 판단합니다. `fec_rec`가 많아도 `lost`가 0이면 화면은 정상입니다.
- ch36으로 되돌려 다시 잰 것(20:11)은 "시간이 지나서 좋아졌다"는 가능성을 지우기 위해서입니다.
- 송신 `dropped = 0`은 WFB-ng 단계까지만 말해 줍니다. 그 뒤(드라이버·동글·전파)에서의 손실은 배제하지 못합니다.
- ch48에서 AP가 안 보였다는 것은 nmcli 스캔에 안 잡혔다는 뜻일 뿐, 간섭이 없다는 확인은 아닙니다.
- MCS3이 4Mbps에서 MCS2보다 나았지만 한 번씩만 잰 값이라 비트레이트와 무관한지는 반복 측정이 필요합니다.
