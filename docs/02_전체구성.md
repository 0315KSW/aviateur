| 송신 | Bash 스크립트 | 무선 서비스 설정과 FFmpeg/GStreamer 실행 |
| 수신 | Zadig 2.9 | 동글 드라이버를 WinUSB로 교체 |
| 수신 | OpenIPC Aviateur v0.3.3 → 수정본(패치 1.1) | 무선 수신, 복호화, FEC, RTP, H.265 디코딩, 표시, 계측 |
| 분석 | `tools/*.py` | 로그·CSV 집계 |

## 데이터 경로

```
Femto Bolt (MJPEG, USB)
  → [GX10] FFmpeg: mjpeg_cuvid(HW 디코딩) → hevc_nvenc(HW 인코딩, H.265) → RTP 패킷화
  → UDP 5602 (GX10 내부)
  → WFB-ng: 암호화 + FEC 8/12 → RTL8812AU에서 802.11 프레임으로 주입(모니터 모드)
  ~~ 5GHz 채널 36 (5180MHz), 20MHz, MCS 1 ~~
  → [Windows] RTL8812AU → WinUSB → devourer(사용자 공간 드라이버)
  → Aviateur 안의 WFB-ng 수신: 복호화 + FEC 복구 → RTP
  → UDP (PC 내부 127.0.0.1) → FFmpeg H.265 디코딩 (DXVA2 하드웨어)
  → 화면
```

## 프로토콜

| 구간 | 쓰는 것 |
|---|---|
| 송신 PC 내부 | RTP over UDP (FFmpeg → WFB-ng, 포트 5602) |
| 무선 구간 | IP/UDP 없음. WFB-ng가 RTP 패킷 1개를 802.11 프레임 1개에 실어 브로드캐스트. 접속·ACK·재전송 없음, FEC로 복구 |
| 수신 PC 내부 | RTP over UDP (Aviateur 내부 → FFmpeg) |
| TCP | 사용하지 않음 |

## 무선·인코딩 설정

| 항목 | 값 |
|---|---|
| 채널 / 폭 | 36 (5180MHz) / 20MHz |
| MCS | 1 (처음 시도한 MCS 4에서는 수신 안 됨) |
| FEC | 8/12 (데이터 8 + 복구 4, 12개 중 4개까지 복구), FEC 타임아웃 10ms |
| link ID / 영상 radio port | 7669206 / 0 (Aviateur 기본값과 같음) |
| 송신 출력 | −1dBm → 10/28 13:37:12부터 15dBm (장치 표시값, 실측 아님). 디스크 설정은 여전히 −1dBm(`wifi_txpower = -100`)이라 서비스 재시작 시 원래대로 돌아감 |
| 해상도 / fps | 3840×2160 / 목표 30fps (실제는 시험마다 16.5~29fps) |
| 코덱 / 레이트 | H.265, CBR 목표 3Mbps, VBV 1Mbit, GOP 30프레임, B프레임 0 |
| RTP payload type | 96 |

### 왜 3Mbps인가
- 목표는 20~25Mbps입니다. 3Mbps는 원인 분리용 임시 값입니다.
- MCS 1·20MHz의 무선 전송 속도는 13Mbps(802.11n 1스트림 표준값)이고, FEC 8/12와 오버헤드를 빼면 영상은 대략 6~8Mbps가 한계입니다(추정).
- 4K·8Mbps·MCS 4로 먼저 시도했으나 수신 화면이 No Signal이어서 MCS 1과 낮은 비트레이트로 낮췄습니다.
- 20~25Mbps는 40MHz·MCS 3~4 이상으로 무선 용량을 늘린 뒤 단계적으로 시험할 계획입니다.

### 왜 H.265인가
- 같은 화질을 H.264보다 적은 비트로 보내서 대역폭 제한에 유리합니다.
- 회의 요구대로 송신(NVENC)·수신(DXVA2) 모두 하드웨어로 처리합니다.
- 코덱은 회의에서 정한 조건이 아니며, 장비에 따라 H.264로 바꿀 수 있습니다(예: 라즈베리파이 4는 하드웨어 인코딩이 H.264 1080p30까지).
